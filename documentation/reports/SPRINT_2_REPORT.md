## Defects found and fixed during the sprint

- **Word upload broke in the production web app.** The Next.js bundler rewrote `createRequire(import.meta.url).resolve('mammoth')` into an internal module number, so the parser worker got a number instead of a path and every DOCX upload failed with "could not be read". Unit tests passed; the E2E run caught it. The worker now resolves mammoth itself and the web app declares mammoth as a dependency.
- **The session link stopped working in an open tab** after the welcome-screen refactor, because the top-level component no longer re-rendered on hash changes. Caught by the CodeAtlas E2E and fixed.
- **Five serious accessibility issues** found by the new scans: low contrast of "inferred" and "observed" badges in CodeAtlas, dimmed rejected suggestions in CVForge, inline links distinguished only by colour, and a logo link whose accessible name did not match its visible text.
- **Stale threat-model rows** (C7, C10 still showed Sprint 1 work as open) and a stale risk status (S-05) were corrected.

## Known gaps, unverified items and security concerns

- **Still not verified in real environments:** live LinkedIn and Naukri pages, and real Ollama output quality. Both need the founder's machine.
- **Accessibility:** automated rules only. No keyboard or screen-reader audit; the extension popup is not scanned.
- **pdf.js parsing is not isolated** in a worker the way Word parsing now is.
- **Delete all local data** leaves CodeAtlas's worktree and clone folders on disk by design (risk K-08).
- **Cancel buttons** are covered by the service test, not by E2E.
- Carried over: DNS rebinding on clone (A16), no clone size cap, fast-forward-only merges, PDF re-parse depends on installed fonts.
- **Verdict: not release-ready.** See the release-readiness assessment for what a public release still needs.
