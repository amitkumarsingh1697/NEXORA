# Language and file-type coverage validation

Date: 2026-11-09. Code: branch `claude/project-thread-5diskb` (the change), compared with `main` at `2228a64` (the baseline). Decisions: [ADR 0014](../architecture/adr/0014-language-and-file-format-registry.md). Gaps before the change: [LANGUAGE_COVERAGE_AUDIT.md](LANGUAGE_COVERAGE_AUDIT.md). Per-language support: [LANGUAGE_SUPPORT_MATRIX.md](LANGUAGE_SUPPORT_MATRIX.md).

## Method

1. **Repositories.** 23 public repositories, shallow-cloned at the commits below, chosen to cover what the request names: polyglot microservices (Go, C#, Python, Java, Node), editors and C (neovim), dotfiles and shell, Terraform, Android and Kotlin, dbt and SQL, C, COBOL, Fortran, Oracle SQL and SQL*Plus, Elixir and Phoenix, Haskell, .NET, Ansible, Nix, PowerShell, Ruby on Rails, PHP and Laravel, Swift, Scala and Play, a large Java monorepo (Keycloak) and a very large Go monorepo (Kubernetes). `hello-world` holds one program in each of about 1,000 languages and stresses identification.
2. **Run.** Each repository was indexed by CodeAtlas core (`indexRepository`, full index, a fresh database per repository), then the brain was built (`buildBrain`). The harness dumped every `file_inventory` row, the index report and the brain coverage.
3. **Independent counts.** For each repository the harness compared the inventory with Git itself:
   - The inventory total must equal the number of paths `git ls-files` lists.
   - The status counts must add up to that total (the inventory invariant).
   - Binary detection was compared with `git ls-files --eol`, which reports `-text` for files Git considers binary.
4. **Rounds.** Run 1 found defects; they were fixed and run 2 measured the fixes; further defects were fixed and the final run below was made on the code in this change. Baseline and final timings were taken back to back on the same machine with a warm file cache.
5. **Kept results.** The per-file inventories, index reports, brain summaries, comparison output and harness scripts are in the project files under `language-coverage/`. `packages/languages/data/validation.json` holds the per-analyser counts that feed the support matrix.

Every number below comes from these runs. Nothing is estimated.

Defects the runs found, each fixed with a regression test in `packages/languages/test/languages.test.ts` or `products/codeatlas/core/test/language-coverage.test.ts`:

- Unrecognised files: certificates and keys (`.pem .crt .cer .csr .key`), keystores, Fortran preprocessor sources (`.fypp`), EEx templates, Apple `.strings`, `.xcconfig`, `.pbxproj` and `.xcstrings`, Java service-loader lists (`META-INF/services/*`), Play `conf/routes` and `conf/messages`, `Dockerfile_windows`-style names, well-known extensionless files (`NOTICE`, `AUTHORS`, `VERSION`, `.nvmrc`, `.python-version` and others), and template suffixes (`.in`, `.tmpl`, `.example`), which are now classified by the inner name and marked inferred.
- Extensionless YAML and INI files are recognised by a bounded line-shape check.
- An empty `beans.xml` failed as XML. Empty files are now `full` with the method "Empty file (nothing to analyse)".
- `.sln` files were read as XML. They now have their own reader, which records the projects they build.
- YAML and TOML found only by content or modeline were marked `failed` when the guess was wrong. A failed parse of a guessed format is now `text`, with the reason.
- JSON5 was sent to the strict JSON parser and failed. JSON5 is now text only.
- `go.mod` was text only, and Go imports were not resolved. `go.mod` now has a reader, and Go imports resolve through the module path to the package folder.

## Binary detection

No file was marked binary that Git does not consider binary. Git considers 14 more files binary than we do in the repositories where the counts differ by detection (1 in hello-world, 1 in microservices-demo, 12 in neovim). They are text in legacy encodings (Windows-1250, ISO-8859-2) or an SVG with control characters; the registry reads them as text, which is the more useful result. In rubygems.org, play-samples, keycloak and kubernetes the remaining differences are files Git calls binary that we exclude before reading (generated, vendored, in a dependency folder or over the file limit); they count as `excluded`, not `binary`.

## Performance

Index time rose on repositories with much non-TypeScript code, because those files are now read and analysed rather than only listed. Profiling during run 2 found a quadratic edge scan when building search chunks, plus hot paths in identifier splitting and comment stripping; those were fixed before the final run (Keycloak went from 32 s to about 23 s in that round). What remains is the cost of the new analysis:

- Kubernetes (+54%): about 19,700 files are now analysed (Go declarations, YAML, JSON and others) where the baseline analysed none, and the larger graph takes longer to store.
- Keycloak (+21%): about 8,700 Java files are now analysed.
- Small repositories show 30 to 300 ms of extra time, mostly from reading files that were previously skipped.
- TypeScript-only workloads and repositories without much new analysis are within run-to-run noise (neovim +1%, fortran-stdlib +4%, play-samples −3%, db-sample-schemas −20%).

Brain build time rose (Kubernetes 0.2 s → 3.4 s, Keycloak 0.3 s → 2.3 s) because the brain now draws up to its 6,000-neuron limit for these repositories instead of a few hundred TypeScript symbols.

## Follow-up round: templates, multi-document JSON, CSV, Graphviz, gettext

A review of the Kubernetes inventory asked why some YAML, JSON, CSV, DOT and other files were text only. Each one was checked; the changes below were then made and the 23 repositories were run again on the same machine.

- **Templates.** Helm, Go, Jinja and `${…}` templates are no longer text only when the document around the tags is valid: a line holding only template tags is blanked, a tag inside a line becomes a placeholder, and the result is parsed and labelled partial ("template placeholders not rendered"). GitHub Actions `${{ }}` expressions are valid YAML and are not treated as templates. A file that is still not valid with placeholders stays text, with the parse error in its reason.
- **JSON objects with placeholders** (for example `cluster/gce/manifests/*.manifest` in Kubernetes) are recognised as JSON by their shape, as an inference.
- **Several JSON documents in one file** are read as a sequence (partial).
- **New readers:** CSV and TSV (row and column counts; cell values are never kept, because `auth-tokens.csv`-style files hold credentials), Graphviz DOT (graph, nodes, edges), gettext `.po`/`.pot` (message counts and language).

## Limitations

- Only TypeScript and JavaScript are analysed by a compiler. Every other language is `partial`: declaration patterns give names, kinds, lines, parameters as written and imports; calls are not traced. Patterns can miss multi-line signatures and macro-generated code and can be fooled by code inside strings.
- Coverage counts files, not lines or symbols. A `partial` file may have had only part of its structure extracted.
- ArchLens inventories never report `full`: files cited by a hand-built model count as `partial`, and everything else readable is `text`.
- Identification relies on GitHub Linguist 9.7.0 data plus overlays. Languages Linguist does not know are "Unrecognised".
- Heuristic identifications (for example `.h` as C, C++ or Objective-C) are marked inferred and list their alternatives.
- These are 23 repositories; other ecosystems can surface new unrecognised files. The harness and per-file outputs are kept so the runs can be repeated.
