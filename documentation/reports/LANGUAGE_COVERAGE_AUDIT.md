# Language and file-type coverage audit (before the change)

Audited code: `main` at `2228a64` (2026-11-09). This is the state the universal language and file-type work starts from. Every gap is cited to the code that causes it. Measured effects on real repositories are in [LANGUAGE_COVERAGE_VALIDATION.md](LANGUAGE_COVERAGE_VALIDATION.md) (baseline columns).

## 1. How detection worked

| Mechanism                                                       | Where                                                                          | What it decides                                                                          |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Extension sets `TS_EXT`, `JS_EXT`, `TEXT_EXT`, `OTHER_CODE_EXT` | `products/codeatlas/core/src/indexer/files.ts:28-62`                           | `FileLang`: one of `typescript`, `javascript`, `markdown`, `json`, `text`, `unsupported` |
| `LANGUAGE_BY_EXT` (26 extensions)                               | `products/codeatlas/core/src/indexer/adapters.ts:98-128`                       | The language name in `unsupportedLanguages`                                              |
| Manifest regexes                                                | `products/codeatlas/core/src/indexer/manifests.ts:31-56`                       | `ManifestKind` (package, ci, container…)                                                 |
| `DEVOPS_FILE` regex                                             | `products/codeatlas/core/src/query/brain.ts:55-56`                             | Which non-code files appear in the brain                                                 |
| `UNREAD_SCHEMA_KINDS`                                           | `products/codeatlas/core/src/query/brain.ts:107-131`                           | Schema sources the brain warns it does not read                                          |
| File-extension tests in the indexer                             | `products/codeatlas/core/src/indexer/index.ts` (`.sql`, `.prisma`, `markdown`) | Which files reach the SQL, Prisma and Markdown readers                                   |
| ArchLens skill                                                  | `skills/archlens/SKILL.md` §3.4, §6                                            | The agent keeps a coverage list by hand; no tooling                                      |

Five independent tables decide what a file is. They disagree: `.sh` is `text` in `files.ts` but a DevOps file in `brain.ts`; `.tf` is in no table in `files.ts` but is a DevOps file in `brain.ts`; `.h` is "C/C++ header" in one place and nothing in the others.

## 3. What already worked and is kept

- Secret-looking files are never read (`isSecretPath`), and the count is reported.
- Tracked files in ignored folders are reported (`ignored_dir`, QA AL-05).
- Size and count limits are reported (`too_large`, `limit`).
- TypeScript/JavaScript analysis through the compiler, with observed/inferred/unknown edges, incremental caching and parse-failure reporting.
- SQL/Prisma/Drizzle table extraction with column types, keys and foreign keys.
- The brain's partial-coverage box and the schema-format warning.

## 4. Consequences for the design

1. One registry must replace the five tables (requirement 8.5: no duplicate or conflicting detection).
2. Every listed path must end in exactly one status bucket with a reason, and the sum must equal the number of paths git (or the walk) listed. This is testable: it is the "no silent omissions" invariant.
3. The status must say what was actually done to the file, from the processing result, not from the format's reputation.
4. ArchLens must run the same classifier, so both products report the same language for the same file.
