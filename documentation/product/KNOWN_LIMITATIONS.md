# Known limitations

Honest list of what does not work, or was not verified, in the current build.

## Verification gaps

- **No real model was exercised.** Ollama was not installed in the build environment. AI paths (CVForge phrasing, CodeAtlas chat, model patches) are tested with fake providers only; quality with real models is unmeasured.
- **Accessibility is checked automatically only.** axe scans cover the screens the E2E journeys reach; there has been no manual keyboard or screen-reader audit, and the extension popup is not scanned.
- **Extension toolbar click is simulated in E2E.** Playwright opens the popup page directly and stubs the active tab; manual testing in Chrome/Edge is still needed, especially on live LinkedIn/Naukri pages (extraction selectors were written against public page structures and a fixture, not verified on live logged-in pages).
- **The ArchLens architecture brain has not been produced in a live Claude Code session.** The renderer, template and model format are tested; the skill's instructions for building a model from a repository link are not.
- **Docker compose file validated (`docker compose config`) but not started**: no Docker daemon in the build environment. Postgres was run natively.

## CVForge

- English resumes and job descriptions only; skill taxonomy is a curated list, not exhaustive.
- Scanned (image-only) PDFs are not supported (no OCR).
- Complex layouts (multiple columns, tables, text boxes) reduce parse confidence; the user must review the confirm screen.
- Two export templates only. The template is the only stored formatting choice besides section order; fonts, margins and spacing are fixed per template.
- Job comparison matches requirements by skill-taxonomy concept. Responsibilities without a recognised skill are not compared across jobs.
- Word and PDF documents that take longer than 20 seconds or more than 256 MB of memory to parse are refused as too complex.
- Single-instance deployment: in-memory rate limiter and local-disk storage.
- Email is written to an outbox folder unless SMTP is configured. SMTP delivery is tested against a local test server only, not a real provider. Email confirmation is enforced only when `REQUIRE_EMAIL_VERIFICATION=true`. There is no CAPTCHA or other bot protection, and no way to change the account's email address yet.
- No organisations/teams yet beyond the personal org created at signup.
- Scores are heuristic and explainable, not predictions of ATS outcomes or hiring decisions.
- PDF export needs fonts metric-compatible with the templates' Calibri and Arial (`fonts-crosextra-carlito`, `fonts-liberation` on Debian/Ubuntu). Without them LibreOffice substitutes other fonts, lines wrap differently, and re-parsing the exported PDF can split one job into two entries (reproduced 2026-11-03 with only DejaVu fonts). Making the parser robust to wrapping is a follow-up.

## CodeAtlas

- TypeScript and JavaScript are analysed by the TypeScript compiler, and so are Svelte, Vue and Astro components (scripts, template expressions and component tags, ADR 0021) and extensionless `#!` scripts. Not resolved in components: Svelte 4 `let:` slot props, Vue components registered globally or auto-imported (Nuxt), a custom SvelteKit `kit.alias`/`files.lib`; event modifiers and CSS are not modelled. 71 other languages are parsed in full by tree-sitter (ADR 0015 and 0019): declarations, parameters, returns, bases, calls and imports, with calls linked by name and type where the source states it, labelled inferred unless a SCIP index confirms them (ADR 0018). Languages with no tree-sitter grammar (Smalltalk, Raku, VBA, VB6, VBScript, VB.NET, RPGLE, JCL, Motorola 68K assembly, Prolog, Mojo, Cython, ABAP, Objective-C++) and about 30 more get classes, functions and imports from declaration patterns, labelled partial. Every other language is identified (GitHub Linguist v9.7.0 data) and searchable as text only. See [LANGUAGE_SUPPORT_MATRIX.md](../reports/LANGUAGE_SUPPORT_MATRIX.md).
- Grammar gaps at the pinned commits show as syntax problems and make the file partial (Swift and Rust were moved to newer commits for Swift 6 and Rust 2024 syntax; other grammars may lag their language in the same way): HLSL `cbuffer … : register(…)`, Haxe `abstract` types, WGSL `alias`, Swift `~Copyable` generic constraints and `case .x():` patterns with empty parentheses (3 of Immich's 29 Swift files, even at the newest grammar commit). In MATLAB, Fortran and VHDL `f(x)` may be a call or an array element; it is linked only when a function of that name is declared. COBOL `PERFORM A THRU B` records the call to A only; a section does not list the paragraphs inside it. Nim procedures are linked as functions, not as methods of their first parameter's type (only `method` declarations are). Vue, SQL, Make, CMake and Dockerfile grammars are built but their files still go to the dedicated analysers.
- Ambiguous extensions (for example `.h`, `.m`, `.pl`, `.v`, `.inc`) are resolved by small content heuristics and a default; such files are marked as identified by a heuristic, with the alternatives, in the inventory.
- Helm templates are recorded as text (they are not YAML until rendered). Liquibase changelogs are read for tables, columns, keys, drops and renames (ADR 0017); changesets in several files are ordered by path, not by `include` order. Lockfiles are counted, not resolved.
- Build, configuration and documentation files (ADR 0022): JSON, YAML and TOML keys and XML elements are read up to 5,000 per file and 32 levels deep (the file is then partial and says so); values are never kept. The brain draws keys and elements three levels deep; deeper ones are in the index and search. Gradle plugins, dependencies and tasks are read by patterns, so ones added by code (loops, helper functions, `subprojects {}` logic) are missed. Class names in XML are linked only to Java, Kotlin, Groovy or Scala source in the repository whose path matches the package. Liquibase `createIndex`, `modifyDataType`, `customChange` and the drop-constraint changes are read as elements but not applied to the schema (those changelogs are partial). AsciiDoc and reStructuredText give nested headings and include links, not searchable prose.
- Git submodules, symbolic links and folders ignored by `.gitignore` are listed as not indexed, with the reason; their content is not read.
- Re-indexing is incremental only while the tsconfig files, package manifests, lockfiles and the set of files stay the same; otherwise it runs in full. A change to a widely imported file re-analyses most of the repository (221 of 451 files for one hono change). Project references and path plugins are untested. The local service indexes at most 20,000 files; the brain command (CLI and ArchLens) has no file-count limit unless `--max-files` is given. Files over 4 MiB are recorded, not read. The ArchLens bundle unpacks about 18 MiB of run-time files to a temporary folder on each run; a run killed with SIGKILL leaves it behind. Large repositories need memory: Twenty (43,891 files) peaked at 8.1 GB, and the commands raise Node's heap limit to three quarters of the machine's memory (at most 16 GiB).
- Service, database and configuration links are heuristics, labelled inferred. Clients created inside functions, and URLs built at run time, are grouped or missed. Configuration values are never read.
- The structure tree goes module → file → symbol; modules are directories, with no separate package level.
- Module overviews written by a model have not been evaluated with a real model.
- Dynamic patterns (dependency injection containers, string-based dispatch, reflection) show up as unresolved or inferred edges, not observed ones.
- Route detection covers Next.js app router and Express-style `app.get(...)` / `router.post(...)` calls; other frameworks are not recognised.
- Ownership and churn need git history; a repository without commits (such as this monorepo today) has no ownership data.
- Secret detection is pattern-based.
- `node:sqlite` is experimental in Node 22.
- Running an untrusted repository's own `test`/`build` scripts executes that repository's code; the allowlist limits _which_ scripts, not what they do.
- Model patches and dependency install need network access (to the model and the registry respectively).
- Single user, single machine by design.
- Local analytics record counts on this machine only; there is no opt-in organisational analytics yet. "Delete all local data" clears the database but leaves the investigation worktrees and public clones folders on disk for you to delete (their paths are shown in Settings).
- Cancelling indexing stops the indexer process; a cancel during the final database commit can still complete that commit.
- Local merge is fast-forward only. If your branch moved after the investigation started, the merge is refused and you start a new investigation from the current commit. Approver identity is the OS user name.
- Public clone: https only, no private repositories, no size cap (10-minute timeout), and the clone request waits for the download before indexing starts. Host checks happen before git resolves the name again, so DNS rebinding is a residual risk (threat A16).
- Frameworks are detected from package.json declarations only; declaration does not prove use. Manifests from non-JavaScript ecosystems are not classified.
- Cycle detection covers resolved file imports; imports CodeAtlas could not resolve cannot form part of a reported cycle.
- Architecture brain: lobe placement (frontend, backend, database, DevOps, core, documentation) is inferred from file paths, imports and node kinds, and can be wrong for unconventional layouts. Parameter and return types are checked only for TypeScript and JavaScript; for other languages they are shown as written in the declaration. The brain keeps up to 100,000 parts (Twenty has 46,088); above that, the most connected are kept and the brain says how many were left out. The 3D view needs WebGL and has been checked only with software rendering in headless Chromium, where a 46,088-part brain loads in 15 s and draws a frame in about 1.5 s (Keycloak, 83,635 parts: about 2.5 s, the same as its 61,811-part brain before build and documentation files were drawn); frame times on a real graphics card are not measured. Above 6,000 parts it uses simpler spheres and no antialiasing.
- Database tables: read from SQL `CREATE TABLE`/`ALTER TABLE`, Prisma models and Drizzle table builders. Views, functions, procedures, triggers, indexes, sequences, types and packages are read from SQL files (ADR 0016): PostgreSQL by its own parser, MySQL, SQL Server, Oracle, Db2 and SQLite by a statement reader that reads tokens, not a complete grammar, so those files stay partial. Names in bodies are matched to tables and routines by bare name, not through the server's search path. SQL built at run time and the Drizzle relational query API (`db.query.x`) are not read. Table use found in SQL strings and Prisma calls is inferred; a SQL string that names a table no schema defines is not linked. Prisma support follows the documentation and was not run on a real Prisma project; a relation over a column renamed with `@map` is not matched. Tables are matched by name across the whole repository, so two products with a table of the same name share one table in the brain. Tables that tests create for themselves (in test files and test, fixtures or mocks folders) are ignored. Temporary tables created by migration code (for example `nodes_next`) appear as tables with no readers.
- ORM schemas (ADR 0017): 23 frameworks are read. Not read: Hibernate `hbm.xml`, JPA `orm.xml`, MyBatis mappers, Doctrine XML and YAML mappings, Flyway Java migrations, EF6 `DbMigration`, and raw SQL inside ORM migrations (`execute`, `RunSQL`, `queryRunner.query`). Partly read: JPA property access (annotations on getters), `@ElementCollection`, EF Core fluent configuration other than `ToTable`, `HasKey` and `HasColumnName`, SeaORM relations. Laravel's plural rule is approximated with Rails' inflections. A Django model whose base class comes from another package counts as a model only when a migration in its app creates it. When several classes share a name and neither scope, C# namespace nor path decides, the reference is left unresolved.
- Compiler-grade references (ADR 0018) need a SCIP index. CodeAtlas runs scip-python and scip-go itself, only with `--run-indexers` and only when they are installed; for Java, Kotlin, Scala, Rust, C#, C, C++ and Ruby you run the indexer in your build and pass `--scip <file>`. Without an index, calls keep the syntax layer's labelled links. scip-python follows the project's Pyright `include` and `exclude`; scip-go needs the Go version the module asks for. Go builtins (`len`, `make`, `append`) and function literals are still counted unresolved. TypeScript and JavaScript already use the TypeScript compiler and ignore SCIP. The web service does not offer SCIP options yet.
- Diagrams: ER, schema and class diagrams only; no Venn diagram. The class diagram lists methods but not properties. Very large schemas are drawn one schema file at a time and capped, with a note saying how many boxes were left out.
