# Security threat model

This is the authoritative threat model. It uses STRIDE per trust boundary. Controls are described in [security/SECURITY.md](security/SECURITY.md), and data handling in [security/PRIVACY_AND_DATA_HANDLING.md](security/PRIVACY_AND_DATA_HANDLING.md).

Status markers:

- **✅ mitigated and tested**: the test is named.
- **◐ partially mitigated**: residual risk stated.
- **○ open**: sprint item named.
- **— accepted**: by design, with the reason given.

Spec §7 says implementing controls does not make a product secure. Residual risks are listed at the end and tracked in RISK_REGISTER.md.

## Assets

| Asset                                                             | Owner          | Sensitivity          |
| ----------------------------------------------------------------- | -------------- | -------------------- |
| Resume files, structured content, confirmations, job applications | CVForge user   | High (personal data) |
| Credentials, session cookies, extension tokens                    | CVForge user   | High                 |
| Source code, git history, secrets accidentally committed          | CodeAtlas user | High                 |
| Integrity of the user's git branches                              | CodeAtlas user | High                 |
| Audit trail                                                       | Operator       | Medium               |

## Trust boundaries

1. Browser ↔ CVForge web/API (internet once deployed).
2. Extension ↔ job-site page (untrusted DOM); extension ↔ CVForge API.
3. CVForge ↔ document parsers (untrusted files).
4. CVForge / CodeAtlas ↔ model provider (local or hosted).
5. Browser and other local processes ↔ CodeAtlas service on 127.0.0.1.
6. CodeAtlas ↔ repository content (untrusted text, including prompt injection).
7. CodeAtlas ↔ git and package scripts in a worktree, and (after S1-1) the user's main worktree during merge.
8. CodeAtlas ↔ remote git host during public clone (after S1-3).

## Residual risks (accepted or open)

- Custom authentication rather than a maintained library (ADR 0009). Mitigated by tests; an external review is recommended before launch (risk S-01).
- No encryption at rest inside the app. This relies on disk and database encryption at deployment (DEPLOYMENT_GUIDE).
- Extension storage encryption is not documented by Chrome (R4). Rotation and reuse detection limit the damage.
- Real-model behaviour under adversarial input is unverified (Ollama not installed).
